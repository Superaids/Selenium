## Shared owner rules — 31 October 2026

At the beginning of every new project/chat, read [GENERAL_RULES.md](GENERAL_RULES.md) and the current [general-rules repository](https://github.com/Superaids/general-rules) (README, AGENTS and linked policies) once when authenticated access is available. Use the checked-in snapshot if unavailable, then read this project's current handover and instructions.

These instructions apply on every device and travel with the repository. When creating a new project/repository, install this portable startup pointer and GENERAL_RULES.md using the canonical tools/bootstrap-project.py or equivalent file writes before implementation and first push. A machine-local rules checkout is only a cache.

Quality bar: elevate concepts and "Blizzardify" games. Ask: **"Would peak Blizzard really be ok with this quality, or how would they make it more compact, easily understandable with amazing game feel?"** Judge actual play, clarity, accessibility, compactness, craft and enjoyment; tests alone do not establish quality or acceptance.

The owner does not pay for GitHub; included Actions usage is scarce. Use local checks. No automatic hosted triggers without a later explicit, scoped owner exception. Useful manual cloud/native checks need owner authorization and a stated usage bound. Do not upgrade billing, change visibility, repeatedly poll CI or push status receipts for an unchanged hosted block. Keep meaningful tests and player-satisfaction monetization rules. This instruction supersedes older after-every-push CI requirements; unrelated stops, approval, privacy and save rules remain in force. Policy 2026-10-31.2.
